# Series folders and agent context

## Roots and startup

- **Workspace root:** contains separate `<series-id>/` folders and shared tooling. No series-specific source, art or QA at this root.
- **Series root:** exactly one named folder directly under the workspace. Contains `AGENTS.md` and `series.json`. Stable lowercase hyphenated `series_id` equals its folder name.
- **Validator root:** explicitly `.` (series root) or `..` (workspace root) in `series.json`. It matches paths stored in the existing production documents. Never blindly replace CLI `project-root` with the series folder.
- **Packages:** each finished chapter is packaged under the series `packages/` directory. Packages are outputs built from QA-passed bytes, not canonical working assets.

An incoming agent reads, in order: workspace instructions → series instructions → `series.json` → selected chapter plan → assigned input files and review evidence. Use `series_workspace.mjs check ... --chapter N` to resolve exact absolute paths and arguments relative to `validator_root`. Check `next_action` and `blockers`, then actual plan dependencies. This bounded lookup avoids scanning every chapter or relying on chat history.

The checker validates index structure/path safety globally, and actual file existence/hashes for shared resources plus the selected chapter. Chapter-bound resources are determined by the chapter resource maps, not their filename/ID prefixes. Unrelated chapter file drift does not block this lookup. `check-jobs` additionally verifies every listed input's current bytes, including previous-chapter continuity inputs.

`context_valid` means metadata paths/hashes are consistent. It never means source accuracy, approval, successful image generation, visual PASS or permission to package. A storyboard's historical approval cannot override a current blocked plan.

## Default layout for new series

```text
<workspace>/
  AGENTS.md
  <series-id>/
    AGENTS.md                         # series rules, source priority, ownership
    series.json                       # resource map + active chapter + next action
    source/
      raw/                            # untouched supplied/canonical intake
      chapter-NN.txt                  # normalized canonical chapter text
    research/
      sources.json                    # inspected Internet/local source records
      world-style.json                # scoped research + art direction
      design-review.json              # actual reference world/style reviews
    design/
      characters/                     # bible, registry, individual versioned refs
      assets/                         # environments, props, symbols, registry/refs
    production/
      plans/chapter-NN.plan.json       # operational truth + evidence + changelog
      manifests/chapter-NN.json        # canonical production manifest
      chapter-NN/
        analysis.json                 # source decomposition and retention
        beat-sheet.json
        storyboard.json
        page-brief.json
        characters/                   # chapter-specific overrides when needed
        assets/                       # chapter-specific overrides when needed
        prompts/                      # actual saved image_gen call arguments
        staging/                      # versioned candidates, never auto-packaged
        final/                        # accepted originals/unchanged-byte copies
        qa/                           # native review evidence, reports, QA receipt
        jobs/                         # persisted assignments and input snapshots
    packages/
      chapter-NN/                     # comic-package.json + pages/page-001.png ...
    archive/                          # immutable superseded metadata/evidence
```

Create chapter folders only when needed. Separate character identities, crowd types and non-character asset IDs. References are individual image_gen outputs referenced through registries, not a collage generated by code. Shared designs live once; chapter overrides use explicit resource selection and scope instead of silently replacing shared identities. An absent research dossier or review remains planned, never a placeholder PASS file.

Canonical image_gen originals may be outside the workspace in the tool's output directory. Keep that genuine original-output path in provenance; only unchanged-byte copies enter this layout. `series.json` registers local copies, while provenance validators check originals. This contract does not weaken imagegen-only constraints.

## Resource index: `comic-series-v1`

Required fields: `schema`, `series_id`, `title`, `layout` (`standard-v1` or `mapped-v1`), `workspace_root` (`..`), `validator_root` (`.` or `..`), `directories`, `resources`, `chapters`, `active_chapter` (number or null), `updated_at` (actual timestamp).

`directories` has series-relative `source`, `research`, `design`, `plans`, `manifests`, `production`, `packages`, `archive`. These declare locations; existing legacy directories need not be renamed. Each resource has one unique ID and path:

```json
{
  "instructions": {
    "path": "AGENTS.md",
    "availability": "present",
    "sha256": "<actual 64-character SHA-256>"
  },
  "world_research": {
    "path": "research/world-style.json",
    "availability": "planned"
  }
}
```

`present` means an existing regular file whose current bytes match `sha256`; it is not an approval status. `planned` means that file does not exist yet and has no hash. Do not overwrite or relabel an existing failed draft as planned. Approval lives in the existing plan/registry/review contracts, avoiding two competing approval ledgers.

Each `chapters` key is an unpadded positive number. A chapter entry contains `root`, a role→resource-ID map, `next_action`, and `blockers` (empty only when actually clear). Optional `staging`, `prompts`, `qa`, `jobs` paths map legacy subdirectories; defaults are below the chapter root.

```json
{
  "13": {
    "root": "production/chapter-13",
    "qa": "production/chapter-13/qa-evidence",
    "resources": {
      "source": "source_13",
      "plan": "chapter_13_plan",
      "storyboard": "chapter_13_storyboard",
      "character_registry": "chapter_13_characters"
    },
    "next_action": "Review researched world design before rendering",
    "blockers": ["World/style review is unresolved"]
  }
}
```

Resource/directory paths are series-relative, without traversal or symlinks. Paths inside existing source/storyboard/manifest documents retain their original resolution root; the helper's `validator_argument` expresses that root accurately. The index is a curated map of current inputs, not an inventory of every historical file. Register exact selected reference files when used in a job; a registry hash alone does not freeze referenced image bytes.

Main agent updates the index after importing/revising a resource, preserves the plan's append-only changelog, and records why inputs changed there. Archive the prior index for meaningful context switches. An index update cannot approve its targets. Before continuing, check selected resource contents and unresolved review results.

## Persisted job: `comic-job-v1`

Store each job under the chapter's mapped `jobs/` folder. Required shape:

```json
{
  "schema": "comic-job-v1",
  "series_id": "example-series",
  "chapter": 1,
  "job_id": "render-01-03-v1",
  "owner": "/root/render_01_03",
  "mode": "production",
  "page_range": {"first": 1, "last": 3},
  "input_snapshot": [
    {"resource_id": "chapter_01_storyboard", "sha256": "<actual hash>"}
  ],
  "writes": [
    {"path": "production/chapter-01/staging/page-01-v1.png", "page": 1},
    {"path": "production/chapter-01/prompts/page-01-v1.json", "page": 1}
  ],
  "report_path": "production/chapter-01/qa/render-01-03-v1.json"
}
```

The example shows shape; include every required source/plan/research/design/storyboard/registry/reference input, with actual registered hashes. QA jobs have `mode: qa`, `writes: []`, their own report and the exact final image/report inputs. Production writes are files under the assigned chapter's staging/prompts, each with its page in range. No worker writes canonical registries, plan, index, manifest, final assets or packages. Reports are within chapter QA. The main agent may promote accepted bytes only after domain gates pass.

`chapter` is a positive integer, not a numeric string. Report/output ownership excludes equal paths and file/ancestor collisions, including paths that cannot coexist as files on disk.

Run `check-jobs` with **all currently concurrent jobs** before dispatch and merge. It checks actual indexed bytes, exact input snapshots, unique jobs/reports/output paths and non-overlapping production page ranges. QA agents may read overlapping pages while writing distinct reports. Source/reference/board changes after dispatch invalidate snapshots; reconcile actual changes and reissue jobs. Never update a snapshot just to make stale work pass.

The checker cannot discover undeclared concurrent jobs, certify completeness of listed inputs or enforce operating-system write permissions. The main agent checks the full active assignment set and actual worker outputs. A report records observed results, actual tool calls/hashes and unresolved issues; a generated template has no PASS claim.

## Existing series adoption

1. Read current series rules and inspect the active chapter's actual plan/board/registries.
2. Create `series.json` with `layout: mapped-v1`, actual root semantics and hashes. Map existing source, design and QA paths. Use per-chapter resource overrides.
3. Keep old assets and metadata in place. Do not mass-rename, duplicate designs, change approved evidence or infer current resources from the largest version number.
4. Add a short startup pointer to series instructions; hash those actual updated bytes in the index. Register planned missing resources honestly.
5. Run `check --chapter N`. New work follows this startup and job contract; legacy files remain traceable until an explicitly reviewed migration.

The helper initializes new series only; adoption is an inspected metadata edit, not a heuristic folder scan or automatic migration.
