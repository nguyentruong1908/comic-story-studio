# Shared production contract

Read once per chapter or changed workflow. Load a domain reference only when that operation needs its schema; do not reload all skills/references for every page. Scope is a correct and complete comic: source analysis, research and design, storyboard, image_gen production, independent native QA and a platform-neutral chapter package. Where the package is later hosted, uploaded or displayed is outside this plugin.

Scripts live in this plugin's `scripts/` folder, not in the comic project. Commands below write `<plugin>/scripts/...`; replace `<plugin>` with the plugin's install path and pass the comic project root as the first argument.

## Invariants

- Read workspace/series instructions and resolve the current plan/resources through `series.json`. Preserve source bytes, scope, stable identities and frozen job inputs. Root alone promotes canonical files. Context/hash validation is not semantic or pixel approval.
- Only Codex image_gen creates or changes art, references, lettering, balloons and effects. Code may inspect metadata, hash and copy unchanged bytes; it never crops, composites, letters or edits art. The only allowed resize is the packager's optional `--mobile` copy, made after QA beside the untouched originals. Record genuine arguments, original output/hash, actual clocks and limitations; never fabricate provenance or review. See [imagegen-only.md](imagegen-only.md).
- Analyze every canonical paragraph/clause, dialogue, thought, description, uncertainty and consequence. Independently review decomposition and every final carrier. Audit units are not layout units: several units may share a panel or natural balloon with exact fragment offsets. Show allowed content directly; adapt only the specifically prohibited element while preserving facts and stakes. See [paragraph-completeness.md](paragraph-completeness.md).
- Before render, approve scoped research, individual character references, necessary asset references, distinctiveness and storyboard. Freeze hashes and the actual preflight start. Source outranks adaptations; choice and inference stay labelled. Refresh changed design/scope, not unchanged evidence indiscriminately. See [research-world-style.md](research-world-style.md).
- Plan actual visible cast/assets, speakers, source realizations, current physical state, action/contact/consequence and facial/body cues. Identity does not lock a neutral pose. Motion/crowd contracts apply where the scene requires them. See [action-expression.md](action-expression.md).
- Reconcile each speech carrier with a visible speaking mouth or an explicitly offscreen/occluded speaker before image_gen. A prompt that labels a character as speaking while also requiring a closed-mouth aftermath state is contradictory and must be split or clarified from the source chronology before rendering.
- Treat speech-mouth contradictions and over-dense panels as blocking pre-render findings: require `speech_mouth_phase: open` (or explicit offscreen/occluded attribution), keep any closed-mouth reaction in a later phase, and expand or split text zones at source-unit boundaries when density exceeds the layout limit. Preserve every source word and carrier.
- Every final page receives independent native inspection of the original image against source and references, with all review domains bound to current bytes. One reviewer may record all domains in one report. An edit invalidates that page's pixel evidence; recheck it and affected adjacent transitions. Reuse unchanged page evidence only with identical image/reference hashes and scope. Never substitute metadata PASS for inspected pixels. See [qa-gates.md](qa-gates.md).
- Run the one blocking QA entrypoint, `validate_chapter_qa.mjs ... --receipt`, for the current input tuple. Other validators are diagnostics; rerun the full gate after any input changes. Only its receipt can be packaged.
- Human review status remains truthful. Honor explicit review deferral; it waives waiting, never internal QA. A chapter is complete when the full gate passes and its package is built and verified.

## Work and storage

Keep one canonical plan, analysis, storyboard and manifest. Reference immutable call/review records by path/hash; avoid embedding the same dossier or arguments in multiple views. Retain actual originals and required evidence. Use compact reversible metadata journals between meaningful phase checkpoints instead of duplicating a full manifest after each page merge: [metadata_history.py](../scripts/metadata_history.py) records semantic changes with raw-hash provenance; replay restores JSON meaning, not original formatting. Preserve exact byte checkpoints referenced by frozen jobs, approvals and QA receipts.

Review original images directly; production needs no HTML galleries or copied image sets. Share already-viewed references within a reviewer session; reopen changed or ambiguous material. Do not emit base64 to text logs or repeatedly redisplay unchanged galleries. Clean only verified rebuildable copies with authorization; retain originals and provenance. Package each finished chapter with [package_chapter.mjs](../scripts/package_chapter.mjs); see [manifest-contract.md](manifest-contract.md#chapter-package).

Each work batch reports completed outputs, real failures, next action, calls/repairs and space used. A recurring defect needs a prompt/reference/root-cause correction before more copies of the same scene. After two unsuccessful targeted repairs, diagnose the invariant and involve another reviewer; do not silently accept the defect or repeat identical edits indefinitely.
